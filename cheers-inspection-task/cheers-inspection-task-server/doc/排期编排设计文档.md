# 巡检任务排期编排设计文档

## 1. 业务背景

### 1.1 问题域

```
用户配置任务 → 系统自动编排 → 生成执行计划 → 机器人执行 → 巡检记录
```

### 1.2 核心挑战

- **时间约束**：任务需要在特定时间点或时间窗口内执行
- **资源约束**：机器人电量、可用性、资源池限制
- **冲突解决**：多个任务竞争同一资源时的分配策略
- **动态调整**：执行异常时的重排机制

## 3. 编排流程

### 3.1 编排步骤

```
┌─────────────────────────────────────────────────────────────────────────┐
```

### 3.2 Step 0: 数据准备

**输入**：
- 待编排的任务列表 `List<ScheduleTask>`
- 编排时间范围 `[startDate, endDate]`

**处理**：
1. 加载资源可用性矩阵
2. 展开每个任务的计划点
3. 构建候选槽位集合

**输出**：
- `ScheduleContext` - 包含资源状态、已排计划点

```java
/**
 * Step 0: 数据准备
 *
 * @param tasks 待编排任务列表
 * @param startDate 编排开始日期
 * @param endDate 编排结束日期
 * @return 初始化后的编排上下文
 */
public ScheduleContext prepare(List<ScheduleTask> tasks, LocalDate startDate, LocalDate endDate) {
    // 1. 加载资源可用性
    for (Long siteId : getSiteIds(tasks)) {
        List<ResourceState> resources = loadResourcesBySite(siteId);
        context.loadResources(resources);
    }

    // 2. 展开计划点
    for (ScheduleTask task : tasks) {
        List<PlannedPoint> points = expandPlanPoints(task, startDate, endDate);
        task.setPlanPoints(points);
    }

    // 3. 构建候选槽位
    context.buildCandidateSlots(tasks);

    return context;
}
```

### 3.3 Step 1: 候选生成

**处理**：
1. 根据 `scheduleMode` 生成候选时间点
2. 应用时间窗口约束
3. 计算允许偏差范围

**三种模式**：

```java
/**
 * 固定时间点模式 (scheduleMode = 1)
 * 用户指定具体时刻，如 09:00、14:00
 */
public List<PlannedPoint> generateFixedTimePoints(ScheduleTask task, LocalDate date) {
    return requirement.getTimePoints().stream()
        .map(time -> PlannedPoint.builder()
            .baseTime(LocalDateTime.of(date, time))
            .earliestTime(minusMinutes(allowAdvanceMinutes))
            .latestTime(plusMinutes(allowDelayMinutes))
            .fixed(true)
            .build())
        .collect(toList());
}

/**
 * 间隔执行模式 (scheduleMode = 2)
 * 按周期或间隔循环执行
 */
public List<PlannedPoint> generateIntervalPoints(ScheduleTask task, LocalDate date) {
    List<PlannedPoint> points = new ArrayList<>();
    LocalTime anchor = requirement.getAnchorTime(); // 08:00
    int cycle = requirement.getTaskCycleMinutes(); // 120分钟

    for (LocalTime current = anchor; current.isBefore(windowEndTime); current = current.plusMinutes(cycle)) {
        points.add(createPlannedPoint(date, current));
    }
    return points;
}

/**
 * 自动编排模式 (scheduleMode = 3)
 * 只指定次数，算法根据策略自动计算
 */
public List<PlannedPoint> generateAutoPoints(ScheduleTask task, LocalDate date) {
    int count = requirement.getDailyExecutionCount(); // 如每天6次
    Duration interval = calculate均匀间隔(windowStartTime, windowEndTime, count);

    return IntStream.range(0, count)
        .mapToObj(i -> createPlannedPoint(date, windowStartTime.plus(interval.multipliedBy(i))))
        .collect(toList());
}
```

### 3.4 Step 2: 冲突分析

**处理**：
1. 检测时间重叠的任务对
2. 构建冲突图
3. 识别资源竞争

```java
/**
 * Step 2: 冲突分析
 *
 * @return 冲突详情列表
 */
public List<SchedulingConflictDetail> analyzeConflicts(ScheduleContext context) {
    List<SchedulingConflictDetail> conflicts = new ArrayList<>();

    // 两两检测冲突
    for (int i = 0; i < tasks.size(); i++) {
        for (int j = i + 1; j < tasks.size(); j++) {
            ScheduleTask task1 = tasks.get(i);
            ScheduleTask task2 = tasks.get(j);

            // 检测时间重叠
            if (hasTimeOverlap(task1, task2)) {
                // 检测资源竞争
                List<Long> commonResources = findCommonResources(task1, task2);
                if (!commonResources.isEmpty()) {
                    conflicts.add(SchedulingConflictDetail.builder()
                        .task1Id(task1.getTaskId())
                        .task2Id(task2.getTaskId())
                        .conflictType(ConflictType.RESOURCE)
                        .involvedResources(commonResources)
                        .build());
                }
            }
        }
    }

    return conflicts;
}
```

### 3.5 Step 3: 联合分配

**处理**：
1. 按优先级排序任务
2. 贪心分配最优槽位
3. 处理固定时间任务优先

```java
/**
 * Step 3: 联合分配
 */
public List<PlannedSlot> allocate(ScheduleContext context) {
    List<PlannedSlot> results = new ArrayList<>();

    // 分离固定时间和灵活任务
    List<ScheduleTask> fixedTasks = tasks.stream()
        .filter(ScheduleTask::isFixedTimeTask)
        .sorted(byPriority())
        .toList();

    List<ScheduleTask> flexibleTasks = tasks.stream()
        .filter(t -> !t.isFixedTimeTask())
        .sorted(byPriority().reversed())
        .toList();

    // 先分配固定任务
    for (ScheduleTask task : fixedTasks) {
        PlannedSlot slot = allocateFixed(task, context);
        if (slot != null) {
            results.add(slot);
            context.recordSlot(slot);
        }
    }

    // 再分配灵活任务
    for (ScheduleTask task : flexibleTasks) {
        PlannedSlot slot = allocateFlexible(task, context);
        if (slot != null) {
            results.add(slot);
            context.recordSlot(slot);
        }
    }

    return results;
}
```

### 3.6 Step 4: 迭代优化

**处理**：
1. 尝试交换冲突任务位置
2. 调整偏差允许范围内的任务
3. 优化资源利用率

```java
/**
 * Step 4: 迭代优化
 */
public void optimize(List<PlannedSlot> slots, ScheduleContext context) {
    for (int iteration = 0; iteration < MAX_ITERATIONS; iteration++) {
        boolean improved = false;

        // 尝试交换
        for (PlannedSlot slot1 : slots) {
            for (PlannedSlot slot2 : slots) {
                if (trySwap(slot1, slot2, context)) {
                    improved = true;
                }
            }
        }

        // 尝试微调
        for (PlannedSlot slot : slots) {
            if (tryFineTune(slot, context)) {
                improved = true;
            }
        }

        if (!improved) break;
    }
}
```

### 3.7 Step 5: 计划输出

**处理**：
1. 生成编排批次 `SchedulePlanDO`
2. 生成执行计划点 `ScheduleDO`
3. 关联资源

```java
/**
 * Step 5: 计划输出
 */
public InspectionTaskSchedulePlanDO output(List<PlannedSlot> slots) {
    // 1. 创建批次
    InspectionTaskSchedulePlanDO plan = new InspectionTaskSchedulePlanDO();
    plan.setPlanCode(generatePlanCode());
    plan.setTotalCount(slots.size());
    plan.setSuccessCount(countSuccess(slots));
    plan.setConflictCount(countConflict(slots));
    planMapper.insert(plan);

    // 2. 创建执行计划点
    for (PlannedSlot slot : slots) {
        InspectionTaskScheduleDO schedule = toScheduleDO(slot, plan.getId());
        scheduleMapper.insert(schedule);

        // 3. 关联资源
        createResourceRelations(schedule.getId(), slot.getResourceId());
    }

    return plan;
}
```

### 4.2 ScheduleTask 定义

```java
/**
 * 编排任务（输入模型）。
 *
 * <p>组合编排所需的各类数据，复用 DO 而非拷贝。</p>
 */
@Data
public class ScheduleTask {

    // ==================== 直接引用的 DO ====================
    private InspectionTaskDO task;
    private InspectionTaskScheduleRequirementDO requirement;
    private InspectionTaskSchedulePolicyDO policy;
    private ResourcePolicy resourcePolicy;

    // ==================== 派生属性 ====================
    private Integer durationMinutes;      // 计算得出
    private Double consumptionPerMinute;    // 从资源获取
    private List<PlannedPoint> planPoints; // 展开得出

    // ==================== 便捷方法 ====================

    /** 从 InspectionContent 计算执行时长 */
    public Integer calculateDurationMinutes() {
        int itemCount = inspectionContent.getObjects().stream()
            .flatMap(o -> o.getItems().stream())
            .toList()
            .size();
        return itemCount * STANDARD_DURATION_PER_ITEM;
    }

    /** 获取站点ID */
    public Long getSiteId() {
        return inspectionContent.getObjects().get(0).getSiteId();
    }

    /** 获取可用资源池 */
    public List<Long> getAvailableResourcePoolIds() {
        return resourcePolicy.getResourcePoolIds();
    }

    /** 展开计划点 */
    public List<PlannedPoint> expandPlanPoints(LocalDate start, LocalDate end);
}
```

## 5. 约束系统

### 5.1 约束类型

| 约束 | 说明 | 优先级 |
|------|------|--------|
| `PlanPointConstraint` | 计划点时间约束 | 高 |
| `BatteryConstraint` | 电量约束 | 高 |
| `ResourceExclusivityConstraint` | 资源互斥约束 | 高 |
| `TimeWindowConstraint` | 时间窗口约束 | 中 |
| `ConflictStrategyConstraint` | 冲突策略约束 | 中 |

### 5.2 约束接口

```java
/**
 * 编排约束接口。
 */
public interface ScheduleConstraint {

    /**
     * 约束优先级（数值越小优先级越高）。
     */
    int getPriority();

    /**
     * 是否适用于该任务。
     */
    default boolean isApplicable(ScheduleTask task) {
        return true;
    }

    /**
     * 验证约束。
     */
    ValidationResult validate(ScheduleTask task, PlannedSlot proposedSlot, ScheduleContext context);
}
```

### 5.3 约束实现示例

```java
/**
 * 计划点约束。
 */
@Component
public class PlanPointConstraint implements ScheduleConstraint {

    @Override
    public int getPriority() {
        return 10;
    }

    @Override
    public ValidationResult validate(ScheduleTask task, PlannedSlot slot, ScheduleContext context) {
        // 检查时间是否在计划点允许范围内
        if (!task.isWithinPlanPointRange(slot.getStartTime())) {
            return ValidationResult.fail("时间超出计划点允许范围");
        }
        return ValidationResult.pass();
    }
}

/**
 * 电量约束。
 */
@Component
public class BatteryConstraint implements ScheduleConstraint {

    @Override
    public int getPriority() {
        return 20;
    }

    @Override
    public ValidationResult validate(ScheduleTask task, PlannedSlot slot, ScheduleContext context) {
        ResourceState resource = context.getResourceState(slot.getResourceId());
        if (resource == null) {
            return ValidationResult.fail("资源不存在");
        }

        // 检查电量是否足够
        if (!resource.canExecuteTask(task.getDurationMinutes())) {
            return ValidationResult.fail("电量不足");
        }

        return ValidationResult.pass();
    }
}
```

## 6. 编排策略

### 6.1 策略选择规则

| 任务数量 | 策略 | 说明 |
|---------|------|------|
| 1 | `GreedyScheduleStrategy` | 单任务贪心 |
| 2-5 | `GreedyScheduleStrategy` | 少批量贪心 |
| 6-20 | `BatchScheduleStrategy` | 中等规模批量优化 |
| >20 | `BatchScheduleStrategy` | 大规模分批处理 |

### 6.2 策略接口

```java
/**
 * 编排策略接口。
 */
public interface ScheduleStrategy {

    /**
     * 编排任务。
     */
    ScheduleResult schedule(List<ScheduleTask> tasks, ScheduleContext context);

    /**
     * 获取策略名称。
     */
    String getName();

    /**
     * 获取适用任务数量范围。
     */
    int[] getApplicableRange();

    record ScheduleResult(
        boolean success,
        List<PlannedSlot> scheduledSlots,
        List<ScheduleTask> failedTasks,
        String message
    ) {}
}
```

## 8. 命名规范

### 8.1 避免歧义

| 旧命名 | 问题 | 新命名 |
|--------|------|--------|
| `ScheduleRuleResourcePool` | 名称包含"Rule" | `ScheduleResourceBinding` |
| `robotPoolIds` | 不够通用 | `resourcePoolIds` |
| `robotIds` | 不够通用 | `resourceIds` |
| `StructuredScheduleRule` | 只是 DO 复制 | 考虑删除或重命名 |

### 8.2 概念澄清

- **Requirement** = 排期需求（用户输入的何时执行）
- **Policy** = 排期策略（算法参数配置）
- **Rule** = 排期规则（具体执行规则）
- **Schedule** = 编排结果/执行计划

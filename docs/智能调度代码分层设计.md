# 智能调度代码分层设计

## 1. 设计目标

代码分层的目标不是把类拆得越多越好，而是让智能调度具备以下能力：

1. 支持单任务试算
2. 支持多任务统一编排
3. 支持资源冲突与时间冲突检测
4. 支持故障后局部重排
5. 支持后续扩展到更复杂的优化器

因此，代码结构必须把：

- 输入标准化
- candidate 生成
- 约束检测
- 求解落位
- 结果构建
- 重排留痕

分开。

---

# 2. 推荐分层总览

建议在 `yudao-module-inspection-task-server` 下新增如下包结构：

```text
service/schedule/
├─ facade/
├─ context/
├─ validator/
├─ candidate/
├─ conflict/
├─ solver/
├─ engine/
├─ result/
├─ reschedule/
├─ persistence/
└─ model/
```

---

# 3. 各层职责设计

## 3.1 facade 层

### 作用

对外提供统一入口。

### 类

#### `InspectionTaskScheduleService`

现有入口接口继续保留，但只作为应用层入口。

建议扩展方法：

```java
SingleTaskSchedulePlan previewSingleTask(Long taskId, LocalDate startDate, LocalDate endDate);
BatchSchedulingResult scheduleTasks(List<Long> taskIds, LocalDate startDate, LocalDate endDate);
BatchSchedulingResult scheduleSiteTasks(Long siteId, LocalDate startDate, LocalDate endDate);
RescheduleResult rescheduleByTrigger(RescheduleCommand command);
```

#### `InspectionTaskScheduleServiceImpl`

职责：

- 接收 controller 参数
- 构造 command
- 调用调度编排门面
- 返回结果

它不负责：

- 直接写 candidate 生成逻辑
- 直接写冲突求解逻辑
- 直接写重排算法

---

## 3.2 context 层

### 作用

把任务定义、排期方案、资源策略等散数据整理为调度引擎输入。

### 类

#### `TaskSchedulingContext`

核心上下文对象。

建议字段：

- task 基础信息
- inspectionContent
- effectiveScheduleProfile
- effectiveScheduleRules
- effectiveResourcePolicy
- estimateDurationMinutes
- estimateDistance
- estimateBatteryConsumption
- priority
- inherit flags resolved values
- parentTaskId
- siteId

#### `TaskSchedulingContextBuilder`

职责：

- 根据 `InspectionTaskDO` 构造上下文
- 解析继承后的有效排期方案
- 解析继承后的有效资源策略
- 整理出可供 candidate / solver 直接使用的结构

#### `TaskSchedulingBatchContext`

批量调度时的上层上下文。

包含：

- 任务上下文列表
- 当前时间范围
- 外部占用
- 资源可用性
- 已锁定计划
- 已存在计划

---

## 3.3 validator 层

### 作用

做规则校验与业务兜底校验。

### 类

#### `ScheduleRuleValidator`

职责：

- 校验 schedule rule 组合合法性
- `schedulePattern` 与字段组合匹配

#### `ScheduleWindowValidator`

职责：

- 校验时间窗开始结束
- 时间窗重叠
- 时间窗连续相接
- 禁止窗 / 候选窗交叉关系

#### `ScheduleResourceValidator`

职责：

- 固定资源策略是否有固定机器人
- 资源池策略是否有资源池范围
- 资源数量要求与策略是否匹配

#### `TaskSchedulingContextValidator`

职责：

- 校验某条任务是否具备可调度条件
- 是否存在有效 profile / rule
- inspectionContent 是否为空

---

## 3.4 candidate 层

### 作用

生成“理论上应该出现哪些候选计划点”。

### 类

#### `InspectionTaskScheduleCandidateGenerator`

统一生成入口。

```java
List<TaskScheduleCandidate> generate(TaskSchedulingContext context, LocalDate startDate, LocalDate endDate);
```

#### `TaskScheduleCandidateGenerationStrategy`

策略接口。

```java
boolean supports(StructuredScheduleRule rule);
List<TaskScheduleCandidate> generate(TaskSchedulingContext context, StructuredScheduleRule rule,
                                     LocalDate startDate, LocalDate endDate);
```

#### 具体策略实现

- `DailyScheduleCandidateStrategy`
- `WeeklyScheduleCandidateStrategy`
- `MonthlyScheduleCandidateStrategy`
- `CustomIntervalScheduleCandidateStrategy`
- `FixedPointScheduleCandidateStrategy`
- `TimeWindowScheduleCandidateStrategy`

#### `TaskScheduleCandidate`

候选计划点对象。

建议字段：

- taskId
- profileId
- ruleId
- scheduledDate
- originalStartTime
- originalEndTime
- preferredWindows
- requiredRobotCount
- fixedRobotId
- resourcePool
- priority
- conflictStrategy
- resourceStrategy
- sourcePattern

#### `SingleTaskScheduleCandidateNormalizer`

职责：

- 单任务候选点排序
- 补默认时间
- 标准化输出

---

## 3.5 conflict 层

### 作用

把候选计划点和现有世界状态做冲突检测。

### 类

#### `TimeConflictDetector`

职责：

- 判断 candidate 与其他计划是否时间重叠
- 判断 candidate 是否落在禁止窗
- 判断 candidate 是否违反延后 / 提前阈值

#### `ResourceConflictDetector`

职责：

- 判断 candidate 在某时间段内资源是否可用
- 判断候选机器人是否被占用
- 判断资源池是否足够

#### `LockedPlanConflictDetector`

职责：

- 判断是否与锁定计划冲突
- 判断某些计划是否不可移动

#### `ExternalOccupationConflictDetector`

职责：

- 判断与外部业务占用是否冲突

#### `BusinessConstraintConflictDetector`

职责：

- 判断父子任务依赖
- 判断先后顺序
- 判断同日 / 同批等业务约束

#### `SchedulingConflict`

冲突结果对象。

字段建议：

- conflictType
- currentCandidate
- blockingScheduleItem
- blockingExternalOccupation
- detail
- resolvable
- suggestion

---

## 3.6 solver 层

### 作用

真正求解“怎么排”。

### 类

#### `HeuristicScheduleSolver`

第一阶段核心求解器。

职责：

- 接收批量 candidate
- 排序
- 逐个尝试落位
- 遇到冲突时选择：
  - 原位
  - 顺延
  - 提前
  - 换资源
  - 标记未排

#### `SchedulingCandidatePrioritySorter`

职责：

- 已锁定优先
- 固定资源优先
- 高优先级优先
- 时间窗窄优先
- 长任务优先

#### `SchedulingSlotSearcher`

职责：

- 在可用时间范围内搜索候选落位点
- 支持向前 / 向后偏移
- 支持窗口内搜索

#### `ResourceAssignmentSelector`

职责：

- 固定机器人优先
- 再从资源池中选择最优可用资源
- 支持简单打分

#### `SolverDecisionTrace`

职责：

- 记录每个 candidate 如何决策
- 便于调试和前端解释

---

## 3.7 engine 层

### 作用

对多步骤编排做统一 orchestrator。

### 类

#### `SingleTaskSchedulingEngine`

职责：

- 单任务试算整合
- context -> candidate -> normalize -> result

#### `BatchTaskSchedulingEngine`

职责：

- 多任务统一编排
- context 批量构建
- candidate 汇总
- 冲突检测
- 启发式求解
- 结果构建

#### `SchedulingEngineCoordinator`

职责：

- 根据 command 选择：
  - 单任务试算
  - 批量排程
  - 重排

---

## 3.8 result 层

### 作用

统一构建输出结果。

### 类

#### `SchedulingResultBuilder`

职责：

- 从 solver 输出构建结果对象

#### `SingleTaskSchedulePlan`

单任务试算输出，现有类可继续扩展。

建议补：

- scheduledCount
- unscheduledCount
- conflictCount
- warnings

#### `BatchSchedulingResult`

批量调度输出。

建议字段：

- scheduledScheduleItems
- unscheduledCandidates
- conflictDetails
- warnings
- summary

#### `RescheduleResult`

重排输出。

建议字段：

- batchNo
- changedScheduleItems
- unchangedScheduleItems
- failedScheduleItems
- summary

---

## 3.9 persistence 层

### 作用

把调度结果写入计划点及相关表。

### 类

#### `TaskSchedulePersistenceService`

职责：

- 保存计划点主表
- 保存资源分配
- 保存冲突记录

#### `SchedulingBatchPersistenceService`

职责：

- 保存批量编排批次号
- 保存调度结果概况

#### `ReschedulePersistenceService`

职责：

- 保存重排批次
- 保存重排变化明细

---

## 3.10 reschedule 层

### 作用

处理设备故障、资源故障、插队任务后的局部重排。

### 类

#### `RescheduleCommand`

重排命令对象。

字段建议：

- triggerType
- triggerSourceId
- siteId
- affectedTaskIds
- affectedResourceIds
- startTime
- endTime
- reason

#### `AffectedTaskScheduleLocator`

职责：

- 找出受影响计划点
- 过滤掉已锁定 / 已执行不可变计划

#### `LocalRescheduleSolver`

职责：

- 只对受影响部分局部重排
- 不全盘推翻未受影响计划

#### `RescheduleImpactAnalyzer`

职责：

- 分析重排影响范围
- 形成变更说明

# 4. 推荐的调用链路

## 4.1 单任务试算

```text
Controller
 -> InspectionTaskScheduleService
 -> SingleTaskSchedulingEngine
 -> TaskSchedulingContextBuilder
 -> TaskSchedulingContextValidator
 -> InspectionTaskScheduleCandidateGenerator
 -> SingleTaskScheduleCandidateNormalizer
 -> SchedulingResultBuilder
 -> Response
```

---

## 4.2 多任务统一编排

```text
Controller / Job / Command
 -> InspectionTaskScheduleService
 -> BatchTaskSchedulingEngine
 -> TaskSchedulingBatchContextBuilder
 -> InspectionTaskScheduleCandidateGenerator(多任务)
 -> ConflictDetectors
 -> HeuristicScheduleSolver
 -> SchedulingResultBuilder
 -> TaskSchedulePersistenceService
 -> Response
```

---

## 4.3 故障触发重排

```text
Event / Command
 -> InspectionTaskScheduleService
 -> RescheduleCoordinator
 -> AffectedTaskScheduleLocator
 -> LocalRescheduleSolver
 -> RescheduleImpactAnalyzer
 -> ReschedulePersistenceService
 -> Response/Event
```

---

# 5. 现有代码与新分层的映射建议

## 5.1 保留并演进

### 已有类可保留

- `InspectionTaskScheduleService`
- `InspectionTaskScheduleServiceImpl`
- `SingleTaskScheduleCandidateNormalizer`
- `TaskScheduleCandidate`
- `SingleTaskSchedulePlan`
- `StructuredScheduleRule`

### 但职责要收紧

例如：

- `InspectionTaskScheduleServiceImpl` 只保留编排入口职责
- `SingleTaskScheduleCandidateNormalizer` 不再承担 solver 角色
- `ScheduleRuleParser` 只做结构转换

# 6. 实施顺序建议

## 第一阶段：重构代码结构，不引入全功能

先完成：

- context 层
- validator 层
- candidate 层规范化
- facade 层瘦身

目标：
单任务试算结构清晰。

## 第二阶段：补批量编排

完成：

- BatchTaskSchedulingEngine
- TimeConflictDetector
- ResourceConflictDetector
- HeuristicScheduleSolver

目标：
支持同站点多任务统一排程。

## 第三阶段：补 persistence

完成：

- task schedule 落库
- 资源分配落库
- 冲突记录落库

目标：
调度结果可保存、可查询。

## 第四阶段：补局部重排

完成：

- RescheduleCommand
- AffectedTaskScheduleLocator
- LocalRescheduleSolver
- 重排记录持久化

目标：
支持故障后局部重排。

---

# 7. 一句话总结

智能调度代码分层的核心原则是：

**把“规则解析、候选计划点生成、冲突检测、调度求解、结果落库、故障重排”拆成独立层次，让单任务试算、多任务统一编排、局部重排复用同一套底层能力。**
